# 🔍 Пошаговая инструкция: Проверка деплоя в Vercel

## ❗ Главный вопрос: Какая ветка задеплоена?

Давайте сначала проверим, что в Vercel задеплоена **правильная ветка** с кодом.

---

## 📋 Шаг 1: Проверяем настройки Vercel

### 1.1 Откройте Vercel Dashboard
🔗 https://vercel.com/dashboard

### 1.2 Найдите ваш проект
Найдите проект с именем типа:
- `cars-backend`
- `cars-backend-kv4l`
- `car-backend-kv4l`

### 1.3 Проверьте текущий деплой
1. Нажмите на проект
2. Вы увидите последний деплой вверху
3. **ВАЖНО:** Посмотрите какая ветка задеплоена

**Должно быть написано:**
```
claude/vercel-deployment-ready-01SyTTZzk2snpS7urgBxqds6
```

**Если написано что-то другое** (например, `claude/analyze-architecture-diagram-...`):
❌ **Это неправильная ветка!** В ней нет кода, только документация.

---

## 📋 Шаг 2: Смотрим детали деплоя

### 2.1 Откройте последний деплой
1. Нажмите на карточку последнего деплоя
2. Вы попадёте на страницу с логами и деталями

### 2.2 Проверьте статус
Вверху должен быть статус:
- ✅ **Ready** (зелёный) - деплой успешен
- ❌ **Failed** (красный) - деплой провалился
- 🟡 **Building** (жёлтый) - деплой в процессе

### 2.3 Проверьте ветку (ещё раз!)
Под названием проекта написано:
```
Branch: claude/vercel-deployment-ready-01SyTTZzk2snpS7urgBxqds6
Commit: ce0a51a
```

**Если НЕ эта ветка** → переходите к Шагу 4 (исправление)

---

## 📋 Шаг 3: Смотрим Build Logs

### 3.1 Перейдите во вкладку "Building"
Нажмите на вкладку **Building** или **Build Logs**

### 3.2 Прокрутите в самый низ
В конце должно быть:
```
✓ Build Completed
✓ Deployment completed
```

### 3.3 Проверьте ошибки TypeScript
Найдите в логах строки с ошибками (красные):
```
error TS2307: Cannot find module...
error TS2614: Module has no exported member...
```

**Если есть такие ошибки:**
- Деплой прошёл, но приложение НЕ работает
- Нужно ждать нового деплоя с исправлениями (я только что запушил)

---

## 📋 Шаг 4: Исправляем ветку (если неправильная)

### Если задеплоена старая ветка без кода:

#### 4.1 Перейдите в Settings
1. В верхнем меню нажмите **Settings**
2. В левом меню выберите **Git**

#### 4.2 Измените Production Branch
1. Найдите секцию **Production Branch**
2. Увидите текущую ветку (например, `claude/analyze-architecture-diagram-...`)
3. Нажмите **Edit** или поле с веткой
4. Измените на:
   ```
   claude/vercel-deployment-ready-01SyTTZzk2snpS7urgBxqds6
   ```
5. Нажмите **Save**

#### 4.3 Создайте новый деплой
1. Вернитесь на главную страницу проекта
2. Вкладка **Deployments**
3. Нажмите кнопку **Redeploy** на последнем деплое
4. ИЛИ нажмите **Create Deployment** → выберите нужную ветку → **Deploy**

---

## 📋 Шаг 5: Проверяем URLs

### 5.1 Найдите URL вашего проекта
В Vercel наверху страницы проекта есть домен:
```
https://ваш-проект.vercel.app
```

Запишите его!

### 5.2 Проверьте разные пути

Откройте в браузере (замените `ваш-проект` на ваш реальный домен):

#### Тест 1: Главная страница
```
https://ваш-проект.vercel.app/
```

**Ожидаемый результат:**
- ✅ Любой JSON ответ
- ✅ Или редирект на `/api`
- ❌ **НЕ 404**

#### Тест 2: Swagger API
```
https://ваш-проект.vercel.app/api
```

**Ожидаемый результат:**
- ✅ Swagger UI (интерактивная документация)
- ❌ **НЕ 404**

#### Тест 3: Admin панель
```
https://ваш-проект.vercel.app/admin
```

**Ожидаемый результат:**
- ✅ AdminJS интерфейс (список таблиц)
- ❌ **НЕ 404** и **НЕ "Cannot GET /admin"**

---

## 📋 Шаг 6: Смотрим Function Logs

### Если всё равно 404:

#### 6.1 Откройте Runtime Logs
1. Vercel Dashboard → ваш проект
2. Вкладка **Deployments** → последний деплой
3. Перейдите во вкладку **Functions** или **Runtime Logs**

#### 6.2 Откройте ваш URL в браузере
Откройте `https://ваш-проект.vercel.app/admin`

#### 6.3 Обновите логи в Vercel
Нажмите **Refresh** в логах

#### 6.4 Ищите ошибки
В логах должны появиться записи:
```
✓ GET /admin 200 (если работает)
✗ GET /admin 404 (если не работает)
ERROR: ... (описание ошибки)
```

**Скопируйте ошибки и пришлите мне!**

## 🎯 Какой URL правильный?

### Ваши варианты URL:
```
https://car-backend-kv4l.vercel.app        ← без 's' в car
https://cars-backend-kv4l.vercel.app       ← с 's' в cars
https://cars-backend.vercel.app            ← короткий вариант
```

**Правильный URL:**
- Тот, который написан в Vercel Dashboard наверху страницы проекта
- ИЛИ на странице деплоя: **Visit** кнопка

### Как узнать точный URL:
1. Vercel Dashboard → ваш проект
2. Наверху большими буквами написан домен
3. Скопируйте его и используйте

**Пример:**
```
┌─────────────────────────────────────────┐
│ cars-backend-kv4l.vercel.app     [Visit]│  ← это ваш URL
└─────────────────────────────────────────┘
```

## 🔍 Диагностика: Почему 404?

### Причина 1: Неправильная ветка (90% случаев)
**Проверка:**
- Vercel Dashboard → ваш проект → Branch: `claude/vercel-deployment-ready-...`?
- Если НЕТ → см. Шаг 4

### Причина 2: TypeScript ошибки при билде
**Проверка:**
- Vercel Dashboard → последний деплой → Building → ищите `error TS...`
- Если ЕСТЬ → дождитесь нового деплоя (я запушил исправления)

### Причина 3: Environment Variables не настроены
**Проверка:**
- Settings → Environment Variables → есть `DB_URL`?
- Если НЕТ → добавьте переменные (см. инструкцию ниже)

### Причина 4: Холодный старт (редко)
**Решение:**
- Подождите 15-20 секунд
- Обновите страницу (F5)
- Первый запрос всегда медленнее

## ⚙️ Environment Variables (если не настроены)

### Минимальные переменные для работы:

1. Settings → Environment Variables
2. Добавьте каждую переменную:

```bash
DB_URL=postgresql://postgres.xxxxx:password@aws-0-eu-central-1.pooler.supabase.com:6543/postgres
DB_SCHEMA=public
JWT_ACCESS_SECRET=any-random-string-32-chars-minimum
JWT_REFRESH_SECRET=another-random-string-32-chars
JWT_WEBSOCKET_SECRET=yet-another-random-32-chars
JWT_ACCESS_EXPIRES_IN=60m
JWT_REFRESH_EXPIRES_IN=30d
JWT_WEBSOCKET_EXPIRES_IN=24h
PORT=3000
NODE_ENV=production
SMS_TEST_MODE=true
```

3. После добавления → **Redeploy**
